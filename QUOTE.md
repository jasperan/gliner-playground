# A quote for the Fastino Labs community page 👋

Fastino Labs reached out asking for a short quote on what you've built with GLiNER.
Here are ready-to-send options — adjust the specifics (project name, link) and send.

---

## Option A — focused on the demo (recommended)

> "I built [gliner-playground](https://github.com/<your-user>/gliner-playground), an
> interactive site where anyone can watch GLiNER2 extract entities, classify text,
> parse structured JSON and link relations — just by typing. What struck me most is
> the zero-shot property: you define the entity types *at inference time*, in any
> language, and a 205M model does in milliseconds what I'd normally reach for a
> multi-billion-parameter LLM for. It's genuinely the sweet spot of
> capability-per-compute for information extraction."

## Option B — shorter

> "GLiNER is the first small model that made me stop defaulting to an LLM for
> information extraction. Zero-shot spans in any language, on CPU, in a single
> forward pass — and GLiNER2's unified interface means one model now handles NER,
> classification, structured data and relations. I built an interactive playground
> ([gliner-playground](https://github.com/<your-user>/gliner-playground)) to show
> people just how easy it is."

## Option C — technical

> "GLiNER2 is the ideal extraction layer for agentic RAG. Instead of a slow,
> expensive LLM call for every document, I use GLiNER2 to pull entities, classify
> the text, and extract structured fields + relations in one pass — then only the
> ambiguous cases get escalated to a larger model. Sub-200ms latencies on a single
> GPU, ~205M parameters, fully CPU-deployable. The schema-driven interface is the
> killer feature: the extraction target is declared, not trained."

### Tips
- Swap the repo URL into your actual repo (or leave it as a placeholder until you make it public).

- If your use case is specific (they love specific use cases), mention the domain: support-ticket PII redaction, contract parsing, news→knowledge graphs, etc.
